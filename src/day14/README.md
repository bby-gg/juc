# Day14 - Fork/Join 框架核心笔记

## 1. 核心概念 (分治思想)
Fork/Join 是 Java 7 引入的并行计算框架，核心思想是**分治法（Divide and Conquer）**：
把一个大任务拆分成若干个互不依赖的小任务（Fork），利用多核 CPU 并行执行，最后把小任务的结果合并起来（Join）。

## 2. 核心类与 API
- **`ForkJoinPool`**：专为 Fork/Join 设计的线程池。
- **`RecursiveTask<T>`**：有返回值的任务（需重写 `compute()` 方法）。
- **`RecursiveAction`**：无返回值的任务。
- **`fork()`**：将任务压入当前线程的队列（异步提交）。
- **`join()`**：阻塞等待子任务执行完毕并获取结果。

## 3. 核心优势：工作窃取 (Work-Stealing)
- **机制**：每个工作线程都有自己的双端队列（Deque）。正常执行任务时从队列**头部**拿。
- **窃取**：当某个线程执行完自己的任务后，它会去其他线程的队列**尾部**偷任务来执行。
- **好处**：充分利用 CPU 资源，减少线程阻塞等待的时间。

## 4. 任务拆分优化建议
- **合理设置阈值 (Threshold)**：拆得太细会导致任务创建和调度的开销大于计算本身；拆得太粗则无法充分利用多核。通常结合实际测试调优。
- **使用 `invokeAll(task1, task2)`**：代替手动的 `task1.fork(); task2.fork(); task1.join(); task2.join();`，底层调度更优。
